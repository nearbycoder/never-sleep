# Releasing Never Sleep

Never Sleep uses Sparkle 2 for native macOS updates. The app checks the signed feed at `https://nearbycoder.github.io/never-sleep/appcast.xml`; each update points to an immutable versioned GitHub release asset and carries an Ed25519 signature. The website's download button uses GitHub's latest-release URL, so it does not need editing for each release.

## What runs automatically

- Pushes and pull requests run formatting, Clippy, app tests, and release-metadata tests on a hosted macOS runner.
- Every push to `main` deploys the website to GitHub Pages.
- Publishing a stable GitHub release refreshes Pages with that release's signed appcast. The workflow copies the exact bytes; it never rewrites a signed feed.
- Sparkle discovers newer build numbers and handles verification, download, installation, and relaunch through its native interface. Users can control automatic checks and updates in the app.

Production signing runs on your Mac. Xcode's cloud-managed Developer ID identity and your local Sparkle signing key are not available to GitHub-hosted runners. No signing password or private key belongs in Git, workflow YAML, or release assets. A Git tag alone intentionally does not publish an unsigned build.

## First-time setup

The repository must be public, with **Settings → Pages → Source → GitHub Actions** enabled. Authenticate `gh` as a maintainer. Xcode must be signed into the developer team with permission to use cloud-managed Developer ID signing. The local development signing identity must be available in Keychain.

The Sparkle distribution is pinned and downloaded by the app build tooling to `target/sparkle`. This project uses the Keychain account `never-sleep`. Its public key is committed as `SUPublicEDKey` in `packaging/Info.plist`; the private key remains in Keychain. Do not generate a replacement key for an existing app. Back up the existing private key securely using Sparkle's documented export procedure before changing computers.

Notarization uses the Keychain profile `never-sleep-notary`. Store credentials interactively if setting up another authorized Mac:

```sh
xcrun notarytool store-credentials never-sleep-notary
```

## Publish a release

1. Bump `version` in `Cargo.toml`, update `Cargo.lock`, and set `CFBundleShortVersionString` in `packaging/Info.plist` to the same value. Increment `CFBundleVersion` to an integer larger than every previous published build. The initial public release is `0.2.0`, build `2`.
2. Run checks, commit the final source on `main`, and push it. Build only after committing: the bundle records its source revision, and publication rejects a different revision or a dirty checkout.
3. Prepare a plain Markdown release-notes file outside tracked source, for example `target/release-notes.md`.
4. Build, sign, notarize, package, and notarize the container:

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
python3 scripts/test-appcast.py

./scripts/build-app.sh
DEVELOPMENT_TEAM=4F2YLTHL8T ./scripts/sign-release.sh
NOTARY_PROFILE=never-sleep-notary ./scripts/notarize.sh "dist/Never Sleep.app"
./scripts/build-dmg.sh
NOTARY_PROFILE=never-sleep-notary ./scripts/notarize.sh "dist/Never Sleep.dmg"

./scripts/publish-release.sh --dry-run 0.2.0 target/release-notes.md
./scripts/publish-release.sh 0.2.0 target/release-notes.md
```

Replace `0.2.0` with the intended version. If more than one development identity is installed, supply `DEVELOPMENT_SIGN_IDENTITY` to the signing script. `SPARKLE_KEY_ACCOUNT` overrides the default Keychain account only when it contains the same public key already embedded in the application.

The publisher checks the source commit, versions, public key, architecture, Developer ID signatures, and stapled tickets. It mounts the disk image and validates the app actually being shipped. It signs and verifies both the update archive and appcast, rejects build-number regressions, creates a draft GitHub release, uploads all assets, then publishes. An interrupted upload can be retried against the same draft and commit. It never replaces an already published release.

Prepared artifacts remain under `target/releases/prepare.*` for inspection. They contain only public material. GitHub release assets are:

- `Never-Sleep.dmg` — custom installer with the notarized application.
- `appcast.xml` — signed Sparkle update feed.
- `SHA256SUMS` — checksums for the disk image and appcast.

The publisher dispatches `pages.yml` after release publication as well. This covers the GitHub restriction that events generated by `GITHUB_TOKEN` do not trigger other workflows. If deployment needs retrying, run the **Publish website and update feed** workflow manually; it always reads the latest stable release.

## Verify delivery

Check that the GitHub release is public, its three assets are present, and the Pages workflow succeeded. Open the website and confirm the download points to the latest DMG. Open **Check for Updates…** from the menu bar in the installed app. For a complete upgrade test, install the previous production build, publish a higher build number, and verify Sparkle offers it and relaunches into the new version. A first public release can validate “up to date”; it cannot yet demonstrate an upgrade from an older updater-enabled release.

The earlier local `0.1.0` prototype had no updater. Install `0.2.0` once using the DMG to receive subsequent in-app updates.
